# 第一版工程核查与改进边界

核查日期：2026-10-15。基线为 1.0.0；本次修复版本为 1.0.1。以下是源码检查与本地模拟验证，不能替代真实账号、复杂仓库、麦克风、外部 MCP 或 Docker 环境的验收。

## 本轮实际改动

- 任务窗口、模型成员页改为真实连接与角色分工；添加模型后返回原任务，不丢需求。
- 工作流、需求分析、群聊和角色分工补充模型入口；角色草稿、群名与成员勾选保留。
- 侧栏可拖动调宽，记住宽度，支持键盘与恢复默认；联系人历史和最近会话支持右键确认删除。
- 模型结果缓存改为 LRU：最多 128 项、序列化键值最多 8 MiB、15 分钟有效期。超过单项容量的结果不缓存；结果读写隔离，避免后续修改污染命中结果。上限不包含 Map 等运行时对象开销。
- 桌面端新增结构化诊断日志与轮转：当前文件最多约 256 KiB，另留 3 份历史；记录版本、时间、启动类别、退出代码和界面崩溃类别，不保存原始 stderr、对话、密钥或任意错误消息。
- “工具与设置 → 诊断日志”和启动错误页可以打开本机日志目录。日志不会自动上传；它用于故障分类，不能替代完整性能分析或崩溃转储。
- 启动总等待时间由 25 秒提高到 90 秒；已确认失败的子进程仍会立即显示对应错误，无需等满时限。

## 对清单中描述的校正

| 描述 | 源码事实与实际影响 |
| --- | --- |
| 全靠一次生成，没有多轮修正 | 流程仍是固定阶段图，但网站/代码可以按总控计划插入前后端阶段；实际沙盒测试失败后已有最多两轮受限修复。不是开放式自主工具循环。 |
| 整个任务只能输出 12 文件 / 30 写入 / 350 KB | 开发提示词要求聚焦 12 文件；`writeFiles` 的 30 条和 350000 字节检查针对每次传入的文件批次。它们不是整个任务全部阶段合计上限。输出空间依然偏小。 |
| 所有阶段最多 6500 tokens | 多数阶段确实较低；PPT 制作阶段已有 12000 的特例。输出上限仍可能限制中型任务。 |
| 审计历史只保存 1000 条 | 完整事件持续追加到 `audit.jsonl`，内存只留最近 1000 条，状态接口只给最近 250 条。旧记录缺少便捷检索、轮转与 UI 分页，启动还会全量读取日志。 |
| 恢复会重跑整个任务 | 已完成阶段保留；失败 / 中断阶段可重新排队。单个模型请求没有跨重启生成断点，重跑该阶段仍可能重复计费。 |
| 普通升级必然让 API Key 失效 | epoch 用于绑定配置与加密文件，阻止旧密钥复活。正常保留用户目录、系统账户及有效密文时不会单因升级自动失效；跨电脑、配置与密文不匹配、加密失败需要重新连接。 |
| 打包不包含测试，质量只靠人工 smoke | 桌面运行包不含开发测试；源码包白名单包含第一层 `.mjs` 自动化测试和检查工作流。已有自动测试和本地模拟浏览器检查，真实环境验收仍不足。 |
| state.json 同步写盘 | 使用异步文件 API、写入队列、临时文件、文件同步与旧版备份；全量序列化和 I/O 放大问题成立，但不是直接使用同步写文件阻塞主线程。 |
| 第二实例完全没有响应 | 第二个进程退出，同时已有实例会被恢复并聚焦；仍不能同时使用两个独立桌面工作区。 |

## 仍成立、尚未在本轮解决的限制

1. **执行引擎**：固定阶段编排，不支持模型任意规划并自主调用工具。MCP 只接 Streamable HTTP，未接 stdio / 独立 SSE / OAuth。审批策略只对受限沙盒提供有限自动批准。
2. **项目规模**：上下文默认最多 100 文件 / 180000 字节 / 单文件 18000 字节，执行阶段还会进一步裁剪。没有增量代码索引、符号检索和覆盖率可视化；不能声称已经理解整个大仓库。默认排除构建目录和依赖是合理起点，但缺少显式安全例外。
3. **测试环境**：Docker 镜像、离线、只读和依赖限制确实影响真实项目。需要增加受控的依赖准备和可写测试副本，不能简单开放宿主命令或默认联网。
4. **交付质量**：网站当前验证只覆盖文件结构；缺少实际浏览器的交互、响应式和可访问性验证。单文件网站和基础 PPT 排版仍限制复杂成果。
5. **输入能力**：链接是 URL 引用，不会自动抓正文；Windows 语音入口是系统听写。没有网页抓取 / 附件解析管线、内置录音转写或模型驱动的可靠类型确认。
6. **数据容量**：会话、消息、模型、技能与 MCP 等有固定上限，缺少归档、分页、选择性导出 / 导入和迁移向导。需求分析只保留最近 50 份，不能等同于全部历史归档。
7. **持久化**：任务状态仍整体保存；长期数据量增加后需要分文件 / 日志化或数据库事务，以及完整备份恢复设计。
8. **分发**：Windows 文件夹版；没有签名、安装器、自动更新、macOS / Linux 发布和多语言。Electron 主程序本身约 246 MB，裁剪 locales 不能明显减小这个主程序；应分清 exe、完整目录与 ZIP 大小。
9. **维护**：较多文件仍是压缩式写法和 HTML 模板拼接。本次只将缓存、诊断抽成可测试模块，没有完成全项目重构。
10. **脱敏**：已知密钥的字面替换不能识别任意编码或变换。日志采用不接收敏感原文的字段白名单；这不代表模型产物、自由文本审计或导出具有完备的数据防泄漏能力。

## 建议实施顺序

1. **可靠数据与可见边界**：归档和分页、导入导出、上下文覆盖提示、审计检索；保持旧数据可恢复。
2. **可验证的执行闭环**：持久化步骤检查点、工具调用状态机、失败恢复与预算控制；用户始终能看到执行证据。
3. **真实项目与交付验收**：增量检索、按模块交付、多文件网站、隔离依赖准备、浏览器验收。
4. **分发与维护**：统一格式化和模块边界、发布渠道、安装与签名、跨平台与语言支持。

这些项目需要分别设计和验收。本轮没有通过取消安全约束或调大几个常量来宣称实现完整自主 Agent。
