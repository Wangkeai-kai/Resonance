# Resonance · 前端优化清单

基线版本：v1.0.1  
整理日期：2026-10-15  
用途：实施排期、开发勾选和交付验收。适用于 Windows 桌面界面及本地浏览器界面。

本文是待实施清单，不表示下列优化已经完成。`[ ]` 表示待完成，`[x]` 仅用于已核对的现状或后续有验证证据的完成项。完成一项时，应补充对应的测试记录或演示截图。

## 1. 目标与现状校正

让回复及时出现、历史消息保持稳定、大图片不重复传输；在此基础上增加编辑、引用、重新生成等对话操作。视觉效果参考现代聊天工具，但验收依据是实际行为与性能，不承诺与 ChatGPT 完全相同。

- [x] 后端已有真实模型流式接收：`model-stream.mjs` 和 `ModelGateway.request(..., {onText})` 能接收生成中的正文。
- [x] 浏览器目前仍通过轮询同步流式正文，回复期间约 1200ms 一次；没有端到端的 SSE 推送。应描述为“后端流式、前端轮询同步”，而非模型完全非流式。
- [x] `drawMessages()` 会重新生成完整消息 HTML；`setHtml` 在 HTML 字符串不变时会跳过 DOM 替换，但仍会重复构造和解析 Markdown。正文变化时会替换整个列表。
- [x] AI 回复的展开状态已有消息身份关联；一般 `details` 的展开恢复仍使用列表下标，需要改为稳定身份。
- [x] 当前页面有 19 个 script 标签、14 份样式表。大部分脚本位于 body 末尾；主题初始化脚本位于 head。不能把全部脚本都当作 head 阻塞脚本处理。
- [x] `runtime.js` 同时承担模型连接等公共功能，不能因为只想延迟高级工作台而直接延迟整个文件。
- [x] 桌面启动等待时间在 v1.0.1 已改为 90 秒；旧建议中的 25 秒不再是当前值。
- [x] 侧栏拖动调宽、会话右键删除、真实模型入口、有界模型结果缓存和基础诊断日志已在 v1.0.1 完成，不重复列作本次前端待办。

## 2. 优先级与实施顺序

| 阶段 | 重点 | 完成后的可见变化 | 前置条件 |
| --- | --- | --- | --- |
| P0 | SSE、按消息增量渲染、接口减负 | 文字及时更新，历史稳定，大会话不反复传图片 | 先约定事件和数据版本 |
| P1 | 乐观发送、引用、编辑与版本、Markdown、图片处理 | 日常对话操作更完整 | P0 的身份与更新机制稳定 |
| P2 | 模块拆分、按需加载、样式整理、性能观测 | 启动和后续维护更可靠 | 保持 P0/P1 的行为回归通过 |

推荐顺序：**数据协议 → 图片传输解耦 → SSE 后端 → 前端增量更新 → 滚动与无障碍 → P0 联调验收 → P1 → P2**。

不要用逐字播放已经完整收到的回答冒充模型实时流式输出；也不要只提高轮询频率来替代这次改造。

## 3. P0 · 实时输出与核心性能

### P0-01 约定可恢复的增量协议

- [ ] 为会话、消息和事件定义稳定身份及递增修订号。
- [ ] 约定初始快照、正文更新、状态变化、完成、失败、停止、删除和重新同步事件。
- [ ] 每个消息事件包含 `chatId`、`messageId`、`requestId`、消息修订号；群聊另外标明成员和汇总身份。
- [ ] 约定游标过期、事件缺失、重复事件、乱序事件的处理方式。

验收标准：

- 重复事件不会重复追加文字或气泡；过期事件不能覆盖较新的状态。
- 仅提供 `afterMessageId` 不算完成：同一条生成中消息也会变化，必须能同步它的修订。
- 服务重启后不能误用上次进程的事件序号；不能续接时明确要求读取新快照。

### P0-02 后端增加 SSE 推送

- [ ] 提供会话事件端点，例如 `GET /api/chats/:id/stream`；最终路径在实现时统一。
- [ ] 将已有 `onText` 更新及时广播，广播与每秒一次的持久化解耦。
- [ ] 正确处理当前 `onText` 的累计正文语义：生成增量或发送有修订号的替换事件，避免把全文反复追加。
- [ ] 支持群聊多位成员同时生成、等待总控、总控汇总及部分成员失败。
- [ ] 处理心跳、客户端断开、慢客户端与有界队列，避免无限积压。
- [ ] 保留现有 loopback、Host / Origin 检查及消息脱敏边界；不推送隐藏推理或凭据。

验收标准：

- 模拟模型尚未结束时，浏览器已显示实际返回的部分正文。
- 推送不等待下一次写盘，不为每个 token 写盘。
- 完成、失败和停止均有明确终态；事件队列溢出时可重新同步。
- 打开、刷新、重连 SSE 只读取状态，不能再次调用模型。

### P0-03 前端按消息身份增量更新

- [ ] 使用 `fetch + ReadableStream` 读取 SSE，处理 UTF-8、跨块事件和换行边界。
- [ ] 按 `messageId` 保留消息 DOM 节点；群聊轮次及任务卡也使用稳定身份。
- [ ] 只更新发生变化的正文、状态和用量信息；历史消息不重新生成。
- [ ] 仅对变化的消息执行 Markdown 解析，并按帧或短时间窗口合并更新。
- [ ] 将通用 `details` 展开状态从下标改为稳定 key，保留已有回复折叠设置。
- [ ] 切换会话时释放旧连接；用会话身份和 generation 防止迟到事件串入新会话。

验收标准：

- 一条回复持续更新时，已完成历史消息的 DOM 对象保持不变。
- 历史文本选择、代码复制按钮焦点、展开状态保持稳定。
- 三位成员同时输出时各自更新，不把总控或成员内容拼到另一条消息上。
- 快速切换会话、主题和页面后，旧事件不会污染当前视图。
- 未完成的代码块、表格、链接仍按安全规则显示，不直接插入未转义模型 HTML。

### P0-04 图片从重复同步载荷中分离

- [ ] 消息同步只返回图片元数据和附件身份，不再反复返回 base64。
- [ ] 增加受限的本地附件读取端点，校验路径、归属、大小和 MIME。
- [ ] 明确旧 dataUrl 消息的兼容方案，保留原始记录与可恢复备份。
- [ ] 前端使用有容量上限的附件缓存；采用 blob URL 时在不再使用后撤销。

验收标准：

- 打开图片后，后续文字更新不再携带图片原始数据。
- 刷新、切换会话和旧数据读取仍能显示图片。
- 删除会话或释放视图后，内存中的附件引用能释放；共用附件不能被错误删除。
- 不因为使用 blob URL 就宣称完成接口减负：网络响应中必须实际去掉重复图片。

### P0-05 拆分轻量状态与降级同步

- [ ] 聊天界面只读取模型身份、当前相关任务及审批等必要状态。
- [ ] 正常流式更新不再反复读取含全部任务和审计切片的 `/api/status`。
- [ ] 初次进入读取快照；后续读取增量或必要的轻量状态。
- [ ] SSE 不可用时提供有退避的同步降级，取消旧计时器，避免两套循环同时运行。
- [ ] 明确页面隐藏、返回前台和任务仍在后台运行时的连接策略。

验收标准：

- 浏览器网络记录中，持续输出不会出现每 1.2 秒一次的完整会话和完整状态响应。
- 降级不会重复提交发送请求，不会出现重叠轮询或无限快速重连。
- SSE 断开后，界面说明正在重新连接；已接收内容保留。

### P0-06 滚动、更新提示与无障碍

- [ ] 保留“接近底部才自动跟随”的行为，增量更新时保持阅读位置。
- [ ] 增加“回到底部”按钮和“有新回复 ↓”提示。
- [ ] 为展开成员回复、加载历史、图片解码后的高度变化保留滚动锚点。
- [ ] 移除整个消息列表的反复 live 播报，使用独立的状态播报区域。
- [ ] 在完成、停止或失败时简短播报；多成员并发时合并提示。

验收标准：

- 向上阅读时新文字不会把页面拖回底部。
- 点击回到底部后恢复跟随；当前已在底部时不显示多余的新消息提示。
- 读屏器不按每个 token 重播整段历史。
- 减少动态效果设置、键盘操作和窄屏布局仍可使用。

### P0-07 断线、停止与一致性联调

- [ ] 覆盖发送后连接中断、读取中断、重连补齐、页面刷新和服务重启。
- [ ] 停止回复后关闭对应前端订阅或停止接收该轮迟到更新，仍接受权威终态同步。
- [ ] 明确“切换视图关闭订阅”和“用户停止模型生成”的区别。
- [ ] 完成后进行一次必要的权威同步，处理正文、终态与用量先后到达的情况。

验收标准：

- 网络重连不会再次付费生成；不确定的发送结果先查询，不盲目重发。
- 停止、完成、失败都不会遗留一直转圈的气泡。
- 重启后保留已持久化的部分内容，明确说明无法恢复未保存片段或模型生成连接。
- 群聊部分失败只重试用户选择的失败成员，已成功成员不重复执行。

## 4. P1 · 日常对话体验

### P1-01 乐观发送

- [ ] 提交时立即显示用户气泡和“正在发送”，使用现有 `requestId` 关联服务端确认。
- [ ] 服务端确认后更新同一气泡，失败就地显示原因及可执行的恢复操作。
- [ ] 将“尚未提交”“已提交结果待确认”“已失败”分开，保留未发送内容和附件。

验收：模拟慢 POST 时立即出现用户气泡；重复点击、超时、刷新和重连不会产生重复消息或重复模型请求。

### P1-02 引用消息追问

- [ ] 为可引用消息增加操作入口，输入框展示引用内容与来源。
- [ ] 支持取消引用、适当截取，并在提交后保留可追踪的引用关系。
- [ ] 引用内容按数据处理，不视作新的系统指令。

验收：引用对象准确，来源被删除或版本切换时有合理提示，引用不会跨会话泄露。

### P1-03 用户消息编辑后重发

- [ ] 先定义历史分支及上下文规则，再实现行内编辑、取消与重新提交。
- [ ] 原消息和原结果可回看，不静默覆盖或删除后续内容。
- [ ] 群聊重发前说明参与成员范围；运行中编辑的行为必须明确。

验收：新回复只使用当前分支上下文；原始记录可恢复，未发出的草稿不丢失。

说明：`requestId` 能帮助去重，但不等于已有历史分支模型，此项不能按简单按钮改动估算。

### P1-04 重新生成与多版本切换

- [ ] 保存同一轮回答的多个版本，增加类似 `‹ 2/2 ›` 的切换入口。
- [ ] 约定单聊、群聊成员和总控汇总各自的版本关联及上下文选择规则。
- [ ] 停止、失败和截断版本也保留状态；区分“重试失败请求”和“生成新版本”。

验收：版本切换不会再次调用模型；主动重新生成才产生新请求，并能看到模型身份与新增用量。

### P1-05 本地代码高亮与 Markdown 改善

- [ ] 引入本地打包的代码高亮实现，检查许可证，只加载必要语言；不使用 CDN。
- [ ] 高亮失败回退纯文本，未知语言不报错，限制大代码块的处理开销。
- [ ] 任务清单使用语义化 checkbox；默认只读，避免误以为点击即修改模型回答。
- [ ] 数学公式和脚注分别评估依赖、离线能力、安全配置与实际需求后再实现。

验收：恶意 HTML、协议链接、未完成代码块和超长输入保持安全；复制得到原始代码而非高亮标记；深浅主题可读。

### P1-06 图片缩放、压缩与处理提示

- [ ] 解码后按像素边长与尺寸限制处理大图片，同时限制解码内存。
- [ ] 区分截图、照片、透明图片和动图；避免小字被过度压缩，明确动图处理方式。
- [ ] 显示处理状态、结果尺寸、预览和取消操作；需要时保留原图选项。
- [ ] 区分本地图片处理进度与真实上传进度，不显示虚假的网络百分比。

验收：大图不会直接卡死界面；图片在最终体积检查后才发送；压缩失败可理解地恢复或提示；截图文字可辨认。

### P1-07 弹窗草稿与键盘效率

- [ ] 群聊创建等弹窗关闭后保留未完成输入，成功提交或明确放弃时才清理。
- [ ] 定义新建对话、快速切换会话、聚焦输入框的快捷键，并提供可查看说明。
- [ ] 避免与输入法、文本编辑、系统快捷键冲突；在输入框内输入 `/` 时不抢夺行为。

验收：误关弹窗可恢复；Esc 和焦点返回正确；中文输入法 Enter、Shift+Enter 继续保持原有行为。

## 5. P2 · 加载与工程整理

### P2-01 拆分公共连接功能与高级工作台

- [ ] 将模型连接等基础能力与高级任务视图拆开，先测依赖关系再按需加载。
- [ ] 按需加载失败时有可重试提示，不让模型入口失效。
- [ ] 审查 script 的执行顺序，决定哪些使用 module / defer；保留必要的主题提前初始化。

验收：首次聊天、首次连接模型、首次打开高级工作台均能独立使用；不出现依赖尚未加载的报错或主题闪烁。

### P2-02 样式去重与统一变量

- [ ] 先记录关键页面视觉基线，梳理样式覆盖关系。
- [ ] 合并重复规则，统一文字、间距、颜色、层级和组件状态。
- [ ] 分批移除补丁式覆盖，而非直接删除旧 CSS 文件。

验收：桌面、浏览器、窄屏、浅深主题的关键截图对比通过；弹窗、菜单和分界线层级正常。

### P2-03 状态与渲染职责拆分

- [ ] 分离会话数据、发送状态、附件状态、界面偏好和连接生命周期。
- [ ] 将巨型模板拆成组件函数，归并事件委托与资源清理。
- [ ] 建立统一 store 或等效的明确状态更新入口，避免多个函数互相全量刷新。
- [ ] 仅追踪生成中消息的等待计时；无等待节点时停止计时，视图离开时释放资源。

验收：同一动作只触发必要更新；反复进入页面不会累加监听器、定时器或 SSE 连接。

### P2-04 构建、资源与可观测性

- [ ] 测量脚本体积、解析时间和首次交互耗时，再决定压缩和拆包方案。
- [ ] 保持离线资源完整，保留第三方许可说明，明确源码与调试映射的分发方式。
- [ ] 记录性能统计而非对话内容：更新次数、耗时、载荷大小与连接状态即可。
- [ ] 将性能与兼容性检查接入自动化验证，并约定固定测试环境。

验收：资源缺失有明确报错；性能数据不包含正文、图片、密钥或账号信息；优化前后有可比较记录。

## 6. 必须保留的回归项

- [ ] Markdown 转义、链接协议白名单、CSP 和 Electron 隔离机制不退化。
- [ ] IME Enter、Shift+Enter、多轮草稿和快捷键不冲突。
- [ ] 私聊隔离，群聊不自动读取其他私聊内容。
- [ ] 模型身份、主模型、成员版本、排队状态与真实调用保持一致。
- [ ] 群聊仍默认展示总控汇总，成员流式输出按需展开。
- [ ] 请求编号去重、停止、手动重试和部分失败恢复继续有效。
- [ ] 添加模型后保留需求、分工、群名和成员勾选。
- [ ] 侧栏宽度记忆、联系人折叠、右键删除、确认弹窗继续可用。
- [ ] 图片与链接、复制代码、导出成果和审批入口不受渲染改造影响。
- [ ] 旧会话可读取；数据格式有变更时先备份，并能回退到兼容方案。

## 7. 验收用例与建议指标

下表是**拟定验收目标，不是已测成绩**。实施前记录基线，固定机器、窗口、模型模拟节奏和数据集；真实模型首字延迟单独统计，不归因于前端。

| 场景 | 验收方法与目标 |
| --- | --- |
| 单聊流式 | 本地模拟每 50ms 输出一块；从服务端收到块到可见更新，建议 P95 不超过 150ms；分别记录首字与完成状态延迟 |
| 三模型群聊 | 模拟成员同时输出并有总控汇总；内容不串位、终态正确、完成后不留等待状态 |
| 稳定历史 | 60 条历史消息加生成中回复；历史 DOM 引用保持不变，只有变化消息重新解析 Markdown |
| 图片会话 | 使用接近现有容量上限的合法测试图片；进入后同步响应不再重复包含历史 base64 |
| Markdown 分块 | 覆盖中文跨字节、跨事件块、代码围栏、列表、表格及危险链接；内容完整且安全 |
| 断网与重连 | 暂停连接后恢复；能补齐或重新读取快照，不再次发送生成请求 |
| 停止与导航 | 停止、刷新、切换会话、切换页面同时发生；无迟到内容污染和重复监听 |
| 用户阅读 | 向上滚动、选中文字、展开代码和成员回复；不抢滚动、不丢焦点或折叠状态 |
| 无障碍 | 键盘和读屏器验证；只播报必要状态，减少动态效果设置有效 |
| 性能对比 | 保存更新次数、Markdown 解析次数、传输字节和长任务记录；在相同数据下比较 |

P0 的必达条件是：**增量协议正确、历史稳定、图片不重复传输、停止与重连不重复付费请求**。响应延迟指标如需调整，应记录原因，不能用打字机动画代替推送链路改善。
