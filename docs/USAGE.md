# Resonance 使用方法

先打开「设置 → 模型连接」，选择服务商，填写 API Key 并选择实际可用的版本。同一 Key 可连接多个版本；Ollama / LM Studio 支持检测本地服务。订阅与 API / 本地分开，未实现的订阅适配会明确标注。

在「设置 → 助理与技能」选择总控和各角色模型。没有单独选择的角色沿用默认配置；总控按任务依赖安排工作，不需要逐个派活。

## 五个入口

- **对话**：点击 AI 联系人单聊，或邀请成员团队群聊。默认看总控汇总，每个成员的回复可独立展开。模型身份与分工直接显示在会话中。
- **项目**：按本地目录查看任务、关联对话、需求、产物和交接摘要。添加项目只是保存目录入口，不会创建代码或读取全部源码。
- **工作流**：内置 PPT、网站、代码、文档和项目计划；支持本地 JSON 导入、导出、自建和钉住。详见 [工作流导入](WORKFLOW-IMPORT.md)。
- **产物**：按类型预览、批注、修改和导出真实任务成果。
- **自动化**：定时与事件触发尚未启用，请手动运行工作流。

模型、技能、MCP 和审批在「设置」集中管理，技术看板位于「设置 → 高级工作台」。

## 制作文件

普通聊天只讨论；想实际制作内容，选择输入框的「交给总控」或运行工作流。新建文档和演示无需选择项目；修改已有代码需选择有初始提交的 Git 仓库。隔离工作树不会自动带入主目录未提交修改。

PPT 请说明主题、受众、页数和已有资料；缺失的产品事实标记为待确认。导出可编辑 PPTX 支持 4–20 页，复杂图片、图表和母版仍待完善。

## 任务中断

任务卡直接显示中断阶段和原因。点「继续未完成步骤」确认后，只继续失败或中断步骤，已完成成果保留；也可先「更换执行模型」。

“模型返回的任务数据格式不正确”表示模型 JSON 无法解析。“模型超时”表示时限内未拿到完整结果，服务商可能已计费；再次继续可能新增用量。程序不会盲目重发这些不确定请求。

“等待前置步骤”表示依赖尚未完成。命令和 Git 操作可能在等待审批，查看操作内容与影响后决定。

## 对话与记录

引用追问把消息放入草稿；编辑重发创建分支并保留原记录。重新生成保留多个回复版本，切换已有版本不调用模型；切换较早轮次会创建分支，避免改变后续上下文。

右键会话可归档、恢复、导出、分支续聊或删除。归档释放最近会话位置。导出 JSON 可能含对话与图片，不应上传代码仓库。侧栏边界可拖动，双击恢复宽度。

输入区支持图片与参考链接，链接不自动抓取网页。Windows 语音按钮打开系统听写，发送前检查文字。

## 保存与分享

桌面数据位于 `%APPDATA%\Gongming`，源码模式默认 `.runtime/`。旧目录名用于兼容 Resonance。图片已独立存储，备份需复制完整工作区。升级通常保留系统加密凭据，跨电脑则可能要重新填 Key。

任务完成不代表已提交或上传。上传 GitHub 使用 GitHub-source 目录；软件 ZIP 放 Releases，见 [上传说明](../GITHUB-PUBLISH.md)。
